# Артефакты для кейса «Приложение инспектора»

## 1. Project Overview

**Приложение инспектора** — мобильный интерфейс для проведения проверок, фиксации замечаний и коммуникации по объекту.  
Проект сфокусирован на полевом сценарии работы: пользователь должен быстро открыть задачу, изучить детали, зафиксировать проблему, прикрепить фотографии и продолжить обсуждение внутри приложения.

---

## 2. Product Goal

Цель проекта — создать понятный и быстрый мобильный инструмент для инспектора, который помогает работать с проверками на месте: просматривать задачи, переходить в карточки, фиксировать результаты, добавлять визуальные материалы и отслеживать дальнейшую коммуникацию по замечаниям.

---

## 3. My Role

В рамках проекта я:

- проработала структуру мобильных экранов;
- собрала логику ключевых пользовательских сценариев;
- продумала навигацию между списками, карточками и вложенными действиями;
- спроектировала сценарий фотофиксации;
- оформила взаимодействие с комментариями и чатами;
- собрала финальный UI мобильного приложения.

---

## 4. Design Task

Основная задача заключалась в том, чтобы упростить рабочий сценарий инспектора в мобильном интерфейсе.  
Важно было сократить количество лишних шагов, сделать информацию легко считываемой и объединить в одном приложении несколько процессов: работу с задачами, фотофиксацию, просмотр деталей и коммуникацию.

---

## 5. User Context

Пользователь работает в мобильных условиях и часто взаимодействует с приложением прямо во время проверки.  
Поэтому интерфейс должен поддерживать быстрые действия, простую навигацию, читаемые экраны и понятные статусы, чтобы пользователь мог сосредоточиться на самой задаче, а не на механике интерфейса.

# UX Artifacts

## 6. User Flow

### Основной пользовательский сценарий

Сценарий построен вокруг быстрой работы с замечанием: от открытия списка задач до фиксации проблемы и продолжения коммуникации по ней.

**Flow:**

Список задач  
→ выбор нужной проверки  
→ открытие карточки  
→ просмотр деталей и статуса  
→ добавление замечания  
→ прикрепление фотографии  
→ выбор источника: камера или галерея  
→ подтверждение вложения  
→ сохранение  
→ дальнейшее обсуждение в комментариях

### Дополнительный сценарий

Список объектов / пунктов  
→ выбор нужной позиции  
→ переход в детальный экран  
→ просмотр информации  
→ обновление данных / статуса

### Коммуникационный сценарий

Список чатов  
→ открытие диалога  
→ просмотр обсуждения  
→ отправка сообщения  
→ возврат к рабочему контексту задачи

---

## 7. Information Architecture

При проектировании приложение было разделено на несколько логических блоков, чтобы навигация оставалась предсказуемой, а рабочие действия — быстрыми и последовательными.

### Структура приложения

**1. Рабочие задачи**
- список задач / замечаний;
- переключение между состояниями;
- переход в карточку.

**2. Карточка проверки**
- основная информация;
- описание;
- статус;
- связанные действия;
- комментарии.

**3. Работа с вложениями**
- запуск камеры;
- выбор изображения из галереи;
- просмотр прикреплённых файлов;
- подтверждение добавления.

**4. Структурные списки**
- объекты;
- пункты;
- категории;
- переход в детальный просмотр.

**5. Коммуникация**
- список чатов;
- диалог;
- обсуждение по задаче.

---

## 8. Key Scenarios

### Сценарий 1. Работа с задачей
Инспектор открывает список задач, выбирает нужную проверку и переходит в карточку, где может просмотреть детали, статус и связанную информацию.

### Сценарий 2. Фиксация замечания
Из карточки пользователь добавляет замечание, вносит информацию по результату проверки и сохраняет её в контексте задачи.

### Сценарий 3. Фотофиксация
Пользователь прикладывает изображения к замечанию через камеру или галерею, чтобы зафиксировать проблему визуально прямо в момент осмотра.

### Сценарий 4. Коммуникация
После фиксации замечания пользователь продолжает обсуждение внутри интерфейса, используя комментарии или чат без перехода во внешние каналы.

### Сценарий 5. Работа со структурированными списками
Пользователь просматривает список объектов или пунктов, быстро находит нужную позицию и переходит к детальной информации.

---

## 10. UX Decisions

### Что было важно в проектировании

**Быстрый доступ к ключевым действиям**  
Основные действия инспектора должны быть доступны без длинных переходов и лишних уровней навигации.

**Понятная структура экранов**  
Каждый экран решает конкретную задачу: просмотр, фиксация, добавление вложений или коммуникация.

**Поддержка полевого сценария**  
Интерфейс спроектирован для использования в движении, поэтому в нём важны читаемость, простая иерархия и короткие действия.

**Связь между задачей и обсуждением**  
Коммуникация встроена в рабочий процесс и не существует отдельно от контекста задачи.

**Фото как часть основного процесса**  
Добавление изображений — не вторичная функция, а один из ключевых элементов фиксации результата.

---

## 11. Outcome

В результате получился мобильный интерфейс, который объединяет несколько рабочих процессов инспектора в одном сценарии:  
просмотр задач, переход в карточку, фиксацию замечаний, добавление фотографий и дальнейшую коммуникацию по объекту.

Проект показывает работу не только с визуальной частью интерфейса, но и с логикой взаимодействия, последовательностью действий и организацией мобильного рабочего процесса.
