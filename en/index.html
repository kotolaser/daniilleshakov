Inspector App

Mobile · UX/UI · User Flow

A mobile interface for conducting inspections, logging findings, and communicating about a site.

Project Overview

Inspector App — a mobile interface for conducting inspections, logging findings, and communicating about a site. The project focuses on a field scenario: the user needs to quickly open a task, review details, record an issue, attach photos, and continue the discussion within the app.

The app is built on top of an existing ERP system that originally worked only on desktop. My task is to take the product logic embedded in it and design a mobile app for a specific client use case.

Product Goal

Create a clear and fast mobile tool for inspectors that helps them work with inspections on-site: review tasks, navigate to cards, record results, add visual materials, and track further communication on findings.

Design Task

Bring the inspection scenario to life in a mobile interface. Make work fast and information easy to read. Combine multiple processes in one app: task management, photo documentation, detail review, and communication.

My Role

  • Collected the logic of key user scenarios
  • Adapted desktop ERP system logic for mobile:
    • Business objects — list view and task filtering
    • Chats
    • File viewing
  • Added the inspection scenario to adapted system sections
  • Designed the photo documentation scenario
  • Created mobile components
  • Designed chat interactions
  • Assembled the final mobile UI

Collaboration

  • Development: core team lead — verified the structure against the product logic the mobile version was based on.
  • Design: design lead — reviewed UX, visuals, and logic for scenario alignment; checked adaptation quality.
  • Design system: design system developer — coordination on mobile components.
  • Management: aligned results at each project stage.

The profile and notification screens were designed by another designer after me — those screens are not included in this case.

Key Scenarios

Working with a Task

The inspector opens the task list, selects an inspection, and navigates to a card with details, status, and related information.

Recording a Finding

From the card, the user adds a finding, enters inspection result information, and saves it within the task context.

Photo Documentation

The user attaches images via camera or gallery to visually record an issue at the time of inspection.

Communication

After recording a finding, the user continues the discussion within the interface using comments or chat.

UX Decisions

  • Quick access to actions — core actions are available without long transitions or extra navigation levels
  • Clear screen structure — each screen serves a specific purpose: browsing, recording, attachments, or communication
  • Field-ready design — interface built for use on the go: readability, simple hierarchy, short actions
  • Task–discussion link — communication is embedded in the workflow, not separated from context
  • Photos as part of the process — adding images is not a secondary feature but a key element of recording results

Outcome

A mobile interface that unifies multiple inspector workflows into a single scenario: browsing tasks, navigating to a card, recording findings, adding photos, and continuing communication about a site. The project demonstrates work not only with the visual layer but also with interaction logic, action sequencing, and mobile workflow organization.

Mobile Condition Constructor

Mobile · UX/UI · Logic Builder

A mobile interface for creating and configuring logical conditions and rules within a product system.

About the Project

A mobile interface project for constructing logical conditions. The user creates rules and conditions through a visual interface without writing code.

Task

Design a clear mobile interface for building complex logical structures. Make the condition configuration process intuitive and accessible for users without a technical background.

My Role

  • Worked out the screen structure for the constructor
  • Built the logic for adding and editing conditions
  • Designed the visual language for blocks and connections
  • Assembled the final UI

Solution

The interface is built on the principle of visual blocks: each condition is a separate element that can be added, edited, or removed. Logical operators (AND, OR) connect blocks into a single structure. Navigation between nesting levels is implemented through screen transitions.

Outcome

The result is a mobile constructor where the user can sequentially create and edit logical conditions without an overloaded interface. The screen structure supports both simple and nested scenarios.

Helios 3 Design System

Design System · UI-kit · Components

A component-based design system: typography, colors, UI elements, interaction patterns, and usage guidelines.

About the Project

Helios 3 Design System — a set of components, rules, and patterns for ensuring visual consistency across multiple products and teams. The system covers typography, color palette, UI elements, and their states.

Task

Create a unified component system that ensures interface consistency across multiple products, speeds up new screen development, and simplifies handoff to developers.
Migrate the existing component library to Tailwind CSS.
The color system should support a large number of themes for different clients.

My Role

  • Defined the set of base components
  • Improved the color palette architecture and typographic scale
  • Ported the size token grid from Tailwind CSS
  • Built a UI-kit with element states
  • Documented component usage guidelines
  • Supported component development

System Composition

Typography

Heading hierarchy, body text, auxiliary styles, sizes, and line heights.

Color Palette

Primary, accent, semantic, and neutral colors with support for a large number of themes for different clients.

Components

Buttons, input fields, cards, navigation, modals, toasts, checkboxes, radio buttons.

Patterns

Forms, lists, tables, dashboards — typical layouts and rules for building them.

Outcome

A component system that ensures visual consistency across products. It speeds up new screen creation and simplifies communication between design and development. Using the Tailwind CSS size grid allowed developers to leverage Tailwind documentation to streamline their work.
